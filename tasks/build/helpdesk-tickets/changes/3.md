# Change request 3

When a client replies to a ticket that is waiting on them, it should go back to In Progress by itself.
Clients can reopen a resolved ticket, but they can't resolve or close tickets themselves.

---

Rerun the full checklist, then check these three additional items. Use the Glassworks Optical client
user from item 25.

33. [Automation] A client reply moves a waiting ticket back to In Progress: as the client user, replying on HD-11843 (Glassworks Optical, Waiting on client) changes its status to In Progress with no other step.
    How to check: As the client user, post a reply on HD-11843; as admin, reload it. Fail if the status is still Waiting on client or anything other than In Progress.

34. [Rule] A client can reopen their company's resolved ticket: as the client user, reopening HD-11968 (Glassworks Optical, Resolved) returns it to an open status, and its earlier resolution note is still on the ticket.
    How to check: As the client user, reopen HD-11968; as admin, reload it. Fail if the client has no way to reopen it, it stays Resolved, or the resolution note is gone.

35. [Permission] A client user cannot resolve or close tickets: on HD-11968 (reopened in item 34) there is no resolve or close control for the client user, and replaying an agent's resolve request with the client user's cookie or token is rejected.
    How to check: As admin, resolve a test ticket with a note and copy that request as cURL; as the client user, look for a resolve or close control on HD-11968 and re-issue the copied request with HD-11968's id and the client user's session; reload as admin. Fail if HD-11968 is resolved or closed.
